# Frozen protocol v1

Primary hypothesis: on the same repeatedly verified repaired S1, actual repair text changes and attributed efficacy/boundary evidence improve valid novel failure discovery versus the same observable history without repair metadata.

Official GEPA 0.0.27 (tag commit 99c3b0ac3b4750cde6a2a88547ed4450930d681b); native tau2 b7ea9074c1cba482b30687fecdb5c8425fd6f619. Native NL evaluator, if required, uses the same Qwen alias; judge semantics remain native.

All LLM roles: openai/dashscope/qwen3.7-plus (HTTP model dashscope/qwen3.7-plus), Chat Completions, temperature 0, enable_thinking false, maximum output 4096, no retry or fallback. Returned alias is not independent proof of backend weights. Fees unknown. Gateway credentials supplied through environment/Keychain.

The machine-readable manifest is authoritative. Seeded shuffle of official train, first four E and next prespecified four V; all forty official test tasks H. No H task text used for development or reflection. Three independent GEPA search seeds 17/29/43. Simulation seed 101, repeat seed 202 for claimed discoveries/repairs. H seed 303, actual pass^1 only. Fixed challenge H generalization uses the first ten official test IDs specified before search. All prompts selected and hashed before any H execution. Historical overlap is conservatively audited: 19 of 40 H IDs appeared in historical JSON; other historical exposure cannot be ruled out. Never claim pristine blindness.

GEPA runs use twelve metric calls, reflection minibatch two, full V, Pareto selection, no merge, skip_perfect_score false. Metric counts are separate from requests. Three search repeats and two alternating cycles per Free/RC arm are planned. Service promotes only a strict V improvement with an E fail-to-pass transition reproduced at both seeds, otherwise stagnates. Customer selection uses V, all reflection uses E. Actual proposed/evaluated candidates and accepted GEPA frontier candidates are distinguished. Initial Customer boundary is fixed text; the native scenario and simulator constraints take precedence over candidate overlays.

Valid discovery: native Customer success under the same Service on each of two simulation seeds; evolved Customer yields native failure on both; independent automatic review on each verifies scenario fidelity, challenge exposure and indexed policy/tool failure evidence. Unresolved and invalid cases score zero. Reviews are automatic, not human validation. Count candidate evaluations, episodes, tasks and mechanisms separately. Task coverage is a conservative novelty statistic; textual mechanism labels require adjudication before being counted as independently established mechanisms. Do not count baseline failures as novel discoveries.

For M3 both arms share S1, E/V task/seed schedule, GEPA settings, initial Customer text, candidate budget and all historical before/after public dialogue evidence. RC additionally sees the true diff, attribution and repair boundary summary. Actual context/token imbalance is reported. Shuffled/length-matched repair is secondary and omitted if the budget cannot sustain it. No repair is invented: if neither M1 nor M2 produces a repeat-verified repair, M3 is scientifically unidentifiable for that repeat. Record this and do not run a falsely named RC control.

The single primary comparison is fixed-S1 Free versus RC. Aggregate within task across search repeats and simulation seeds; resample task clusters 10,000 times with RNG 1729 for 95% percentile CI. Exploratory small-sample results; no claimed statistical power. Repeated episodes are not independent tasks. Alternating branch divergence does not identify the causal effect of a single repair message. Additional comparisons are descriptive.

Global request cap 30,000, reservations durable and atomic before sends. Failed sends, interrupted reservations and retries count; counters never reset on resume. Pre-H 16,000 / protected H 14,000 nominal planning allocation. Completed episode cache includes task/seed/prompts/condition/model/manifest identity. Original GEPA run_dir is used for state recovery. Partial transport failures retain raw requests and interruption evidence; no zero reward fabricated for infrastructure failures.

Implementation clarification before M3/H (v1.1): always attempt the two predefined alternating cycles even when M1/M2 finds no repeat-verified repair. Such starting customer searches are named M4-start, not M3, and are not eligible for the primary causal comparison. If M4 produces a first repeat-verified repair, choose it in the predefined Free-then-RC, ascending-cycle order and run the same fixed-S1 M3 comparison afterward. Never select a repair pair by Free/RC results. Precompute the shared native-customer reference episodes before either M3 arm to avoid assigning shared control cost disproportionately to Free.
